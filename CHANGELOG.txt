v1.8.4  -  2026-10-25   (trial page only)
---------------------------------------------------------------------
CHANGED (from tester question)
- In "Check the runners", a runner who scored from 1st or 2nd now has
  an "Out at..." button that asks where the out happened (2nd, 3rd or
  home). The run comes off the board, one out is added, and the play
  log names the right base. Example: triple with runners on 1st and
  2nd, the lead runner is out at 3rd, the other still scores.
- Error and RBI tagging for plays like this is left for the real build.


---------------------------------------------------------------------
v1.8.3  -  2026-10-24   (trial page only)
---------------------------------------------------------------------
ADDED (from tester feedback)
- "Check the runners" card after any hit, walk or error that moves
  runners. Each runner the app moved gets one-tap fixes: "Held at 3rd"
  (run and RBI taken back) or "Out at home / 3rd / 2nd".
- It only offers what's possible: with runners on 2nd and 3rd, holding
  the runner at 3rd also sends the other runner back to 2nd; with the
  bases loaded nobody can hold, so no Held buttons show.
- "Looks right" hides it; it also goes away on the next play. Undo
  brings it back along with the play.


---------------------------------------------------------------------
v1.8.2  -  2026-10-24   (trial page only)
---------------------------------------------------------------------
ADDED (from tester feedback)
- Home plate is tappable: one menu for everything at home. Runner on
  3rd scores (with or without the RBI) or is thrown out at home; a
  runner the app scored on the last play can be marked thrown out at
  home (run and RBI taken back, out added) or held at 3rd.
- Runner menus say what happened: "Thrown out at home / 3rd / 2nd",
  plus "Out on the bases" for doubled off, picked off, etc.
- These outs work for Saucers runners too (not just the opponent),
  count toward the 3 outs, and show in the fans' play-by-play.


---------------------------------------------------------------------
v1.8.1  -  2026-10-24   (trial page only)
---------------------------------------------------------------------
FIXED (from tester feedback)
- A runner the app moved too far can be held: tap the base he should
  be on and pick "Move Tommy here", or tap his base and pick "Held at
  2nd". Before, runners already on base weren't in the list.
- A runner the app scored on a hit can be put back: tap the base and
  pick "Tommy didn't score". The run, his R and the batter's RBI are
  taken back.
- Runners still move on their own by default; these are quick fixes
  for the exceptions. Every fix shows in the play-by-play and can be
  undone.

v1.7  -  2026-10-20   (sw.js cache: saucers-v9)
---------------------------------------------------------------------
ADDED
- Game picker on the Publish screen: Game 1, Game 2, Other, or
  Don't log (practice / test publishes that skip the log).
- Game date box (defaults to today; set it to the game day when you
  publish ahead of time).
- Game log: every publish also saves a record to games.json in the
  repo: date, game number, game note, time, field, and the batting
  order with each player's position (or bench). Publishing the same
  date + game again replaces the earlier record instead of adding a
  duplicate. Game 1 and Game 2 are separate records, so changes
  between games are tracked.
- Game log viewer (Publish screen > Game log): per-player totals
  (games in the lineup, games on the field, games on the bench, and
  how many times at each position) plus the list of games.
- Team view shows "Game 1 of 2" / "Game 2 of 2" when a game is picked.
  The WhatsApp message title says "Game 1" or "Game 2" too.
- If the game log can't be saved, the lineup still publishes and the
  screen says so. Publish again to retry.
NOTES
- The log is public in the repo, like the lineup, but it uses first
  names / nicknames only (Tova, Chez, Anthony G.), never full names.
- The published team lineup still shows full names. (Open question.)
- Innings are not tracked yet, only who is in the lineup and where.
  Mid-game substitutions would need a sub button (V3 idea).

PLANNED
---------------------------------------------------------------------
V2

V2 / V3

V4
- League edition: scale the app beyond one team, for the league
  commissioner and a place to keep standings for our division. Many
  teams, schedules, scores and standings, with each team managing its
  own lineup. To be worked out when we get there.
V2 / V3: Scorekeeper and live Gameday (design agreed 2026-10-24)
- Scorekeeper view: 7-inning line score (Away always on top, R and H),
  inning, outs (3 dots), and a diamond where tapping a base moves,
  scores or removes a runner. Saucers logo on home plate (need file).
- Saucers at bat: scorekeeper picks the leadoff hitter each inning,
  then taps the result: Walk, 1B, 2B, 3B, HR, Fly / Line / Ground out,
  Strikeout. It moves to the next batter and tracks AB, H, R, RBI,
  BB, K. Also: Sac fly, Fielder's choice, Error (approved).
- Opponent at bat: same result buttons with no names, plus +1 Run and
  +1 Out. Third out flips the half-inning and fills in a 0.
- "We are Home / Away" picked per game.
- Final button any time (blanks the rest of the innings), Extra inning
  button. Mercy rule: 10+ runs after 4 innings, losing team always
  gets its last chance (app asks, never ends the game on its own).
- Team view = basic MLB Gameday: score, inning, outs, runners, batter
  and on deck, last play, play-by-play, Saucers box score.
- Scorekeepers: the two clipboard keepers share one score-only key that
  can't change the lineup.
- Hosting: trial on GitHub (separate score repo published by a GitHub
  Actions workflow, about a minute behind, since plain Pages allows
  only ~10 rebuilds an hour). Move to a Cloudflare-style live service
  once it's a solid V2.
- Mock-up built (private claude.ai page), then shared as the v1.8 trial.
  Approved: opponent buttons, auto runner moves, mercy / walk-off
  prompts, named Undo, and keeping the Sac fly / FC / Error buttons.

V2 / V3 additions
- Formal name plus a nickname / alternate name for each player, so the
  stats show the right name while the lineup keeps using nicknames.
  (Decided: the published lineup and game log stay as they are for now.)
- Mid-game substitutions: the scorekeeper taps players in and out
  during the game, which gives real innings / playing time. Goes with
  the live score feed.
Official app (decided direction, 2026-10-27)
- One domain, three doors: / team view (public), /score scorekeepers
  (code), /manage manager (real login). Moves off GitHub Pages to
  Cloudflare (pages + worker + database, free tier). Roster and injury
  notes live privately on the server; the public side only gets what
  the team view needs.
- Every at-bat stored as an event so stats, Undo and take-backs all
  come from one log. Offline queue for the scorekeeper (bad field
  signal). team_id on every record so V4 league edition is adding
  teams, not a rebuild. Import existing lineup.json / games.json, then
  retire the GitHub token.
- Order: 1) domain + team view + manager login, 2) scorekeeper + live
  scores, 3) season stats / player profiles, 4) league edition.
- Build after the season, Opus at high effort. Open questions: domain
  name (about $12/yr), one shared scorekeeper code vs one per person,
  manager login (email link / passkey), co-manager, team view public
  vs behind a team code.

Roles and logins (proposed by Matt 2026-10-27, refined)
- Fan: no login. Live score, standings, player stats, lineup. First
  names only.
- Clipboard: a team code (manager can change it). Enters plays for that
  team's active game only. Cannot touch roster or lineup.
- Manager: real login. Edits that team's roster and lineup, publishes,
  injured list, issues the Clipboard code. Only their own team.
- Admin: real login. Two levels: Matt (platform owner) and Chris
  Ostrow (commissioner, admin of his league only). Manages teams,
  standings, any game result. Every admin edit is logged.
- Private details (full names, injuries, notes) visible to Manager and
  Admin only.
- Open design question: who enters the opponent's results for the
  standings. Leaning: a game is official once both managers confirm,
  with a conflict flag for the commissioner.
- Sequencing: build the Saucers side first (Fan, Clipboard, Manager)
  with Admin designed in; league features wait until Chris is on board.
- Domains: Nicholls Tech has none yet. Plan two cheap ones: the
